# Tasks

Простой таск-трекер — упрощённая Jira. Верхний уровень — **юниты**: это кросс-функциональные команды (внутри работают ASO, Design, iOS и т.д.), у каждой своя доска, задачи и набор полей.

Хостинг — **Cloudflare Workers** (статика), данные — **Supabase** (Postgres + вход по email). Сервер не нужен.

**Роли** (концепция — [docs/CONCEPT.md](docs/CONCEPT.md))

| | CEO | PM | RM / Lead / сотрудник |
|---|---|---|---|
| Юниты | все | свои | свои |
| Приложения | все: создать, перенести, статус | своих юнитов: статус | своих юнитов |
| Задачи | все | своих юнитов | своей позиции и команды, свои |
| Создать / удалить задачу | ✅ | в своих юнитах | — |
| Двигать задачу | ✅ | в своих юнитах | свою, если заполнены обязательные поля |
| Разложить запрос по флоу, передать в релиз | ✅ | в своих юнитах | — |
| Люди, позиции | ✅ | ✅ | — |
| Роли и доступы | ✅ | — | — |

CEO переключается между режимами Default (только приложения) и Admin (всё). Режим разработчика (`people.is_dev`) — «смотреть как», шорткаты-сценарии и тестовые данные.

Права проверяются в базе (RLS + триггеры в `supabase/schema.sql`), интерфейс лишь прячет недоступное. Сотруднику вместо главной показывается личный дашборд.

**Возможности**

- Юниты — направления (Gold, RF, MVP…): состав с позицией каждого (человек может быть в нескольких юнитах), настройка, дублирование, архив
- Приложения со статусами и приоритетом; запросы CEO → этапы по флоу юнита с зависимостями (заблокированный этап не сдвинуть) → релиз у RM
- Дашборды по ролям: CEO (портфель, требует внимания, работы в ходу, недавно вышло), PM (входящие, этапы, проблемы, KPI команды), RM «Релизы» (очередь, ревью Apple, реджекты), сотрудник и лид (фокус, ревью, загрузка позиции)
- Канбан приложений: статусы × юниты; карточка релиза с шагами «Отправил в Apple / Вышло в стор / Реджект» и автостатусами
- Моя доска у каждого: обязательные колонки To Do / In Progress / Review / Done и свои между ними
- Режим разработчика: «смотреть как», шорткаты-сценарии (New App, Демо-процесс), тестовые данные
- Позиции и команды людей; позиция у задачи подставляется по исполнителю
- Доска со своими колонками в каждом юните (добавить, переименовать, цвет, тип «не начато / в работе / готово», порядок, удаление с переносом задач), колонки тянутся на всю ширину
- Дорожки по отделам на доске, вид «Список» с сортировкой, drag & drop
- Задачи: номер вида `DEV-12`, исполнитель, срок, описание, чеклист, комментарии, история изменений
- Настраиваемая карточка: 9 типов полей, обязательные поля, показ на карточке
- Фильтры: поиск, исполнители, отделы, значения полей, просроченные, архив
- «Новое для вас»: назначение, ревью, «Вернули», «Закрыта по ревью», «Можно начинать», сроки; «Мои задачи» по всем юнитам
- Глобальный поиск `⌘K`, горячие клавиши (`C` — новая задача, `/` — поиск, `?` — подсказка)
- Вход по ссылке на email, светлая/тёмная тема, мобильная вёрстка

## Запуск в продакшене: Supabase + Cloudflare

### 1. Supabase (≈5 минут, бесплатный тариф подходит)

1. Создайте проект на [supabase.com](https://supabase.com).
2. **SQL Editor → New query**: вставьте содержимое [`supabase/schema.sql`](supabase/schema.sql) и нажмите **Run**. Скрипт создаёт таблицы, функции и правила доступа; его можно запускать повторно.
3. **Authentication → Sign In / Providers → Email**: оставьте Email включённым. В настройках Auth выключите **Allow new users to sign up** — в команду попадают только приглашённые.
4. **Authentication → URL Configuration**: в **Site URL** и **Redirect URLs** укажите адрес сайта, например `https://task-boart-hsym.norinnort4.workers.dev/**` (и `http://localhost:5177/` для разработки).
5. **Authentication → Policies (пароли)**: минимальная длина — 8.
6. Создайте себе вход: **Authentication → Users → Add user → Create new user** (email, пароль, Auto Confirm). При первом входе в пустой сервис вы станете CEO; режим разработчика включается SQL (см. ниже); остальных людей добавляйте уже из приложения.
7. **Project Settings → API**: скопируйте **Project URL** и ключ **publishable** (anon).

### Аккаунты: серверная функция `admin-users`

Создание входа, сброс пароля и блокировка требуют секретного ключа, поэтому работают в Supabase, а не в браузере:
**Edge Functions → Deploy a new function → Via Editor**, имя `admin-users`, вставить [`supabase/functions/admin-users/index.ts`](supabase/functions/admin-users/index.ts), **Deploy** (Verify JWT — оставить включённым).
После этого в «Люди и доступы» можно добавить человека с email — приложение покажет временный пароль, который нужно передать коллеге.

### Обновление существующей базы до ролей

1. SQL Editor: выполнить новый `supabase/schema.sql` целиком.
2. Сразу назначить себя CEO (и, если нужно, включить режим разработчика) — подставьте свой email:
   ```sql
   update people set access = 'superadmin', active = true where lower(email) = 'you@company.com';
   update people set is_dev = true where lower(email) = 'you@company.com';
   ```
3. Задеплоить фронт (push в `main` — Cloudflare соберёт сам). Профили коллег привяжутся к аккаунтам по email при их первом входе; позиции назначьте в «Люди и доступы».

> Ключ `anon` публичный по замыслу Supabase — его можно класть во фронт. Доступ к данным закрыт правилами RLS: читать и писать могут только вошедшие пользователи.

### 2. Cloudflare

Сайт собирает и выкатывает Cloudflare (Worker со статикой из `dist`, настройки в [`wrangler.jsonc`](wrangler.jsonc)) на каждый push в `main`. Подробно — [docs/deploy-cloudflare.md](docs/deploy-cloudflare.md): подключение репозитория, переменные `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`, адрес для Supabase Auth, откат в один клик.

При первом входе приложение предложит создать профиль (или выбрать себя, если вас уже добавили в «Люди» без email).

## Локальная разработка

```bash
npm install
cp .env.example .env.local   # вписать ключи Supabase — или пропустить
npm run dev                  # http://localhost:5177
```

**Без ключей** приложение работает в **локальном режиме**: та же схема Postgres (PGlite, WebAssembly) крутится прямо в браузере, данные хранятся только в этом браузере. Удобно для разработки и демо; в интерфейсе видна плашка «Локальный режим». Входа нет: старт — аккаунт **«Разработчик»** (CEO с режимом разработчика). Роли проверяются через меню профиля → **«Войти как…»** или **Режим разработчика → «Смотреть как»** (правила доступа применяются как к выбранному человеку). Кнопка «Заполнить демо-данными» на пустом дашборде создаёт студию: юниты Gold / RF / MVP, CEO, двух PM, RM, лидов дизайна и iOS, сотрудников, шесть приложений на всех стадиях — от входящей задачи CEO до реджекта и стора. Режим разработчика → «Демо-процесс» добавляет то же самое поверх текущей базы как тестовые данные.

| Команда | Что делает |
|---|---|
| `npm run dev` | Vite с HMR |
| `npm run build` | Сборка в `dist/` |
| `npm run preview` | Просмотр собранной версии |
| `npm test` | Проверка кода (ESLint) и тесты бизнес-логики и прав доступа на настоящем Postgres (PGlite) с `supabase/schema.sql` |
| `npm run lint` | Только проверка кода: необъявленные переменные (сломанные импорты), лишний код |

## Устройство

```
supabase/schema.sql      таблицы, роли, SQL-функции, триггеры и правила доступа (RLS)
supabase/functions/      admin-users — аккаунты для входа (Edge Function)
web/
  index.html
  src/
    main.js              старт, вход, горячие клавиши
    data.js              выбор хранилища: Supabase или локальный PGlite
    backend.js           вся бизнес-логика (методы API) поверх supabase-js
    pglite-client.js     совместимый с supabase-js клиент над PGlite (локальный режим, тесты)
    api.js               вызов методов с очередью записей
    router.js            маршруты в hash: #/, #/apps, #/board, #/my, #/admin, #/dev, #/u/:unit[/list|/settings][?task=:id]
    state.js, ui.js      состояние, хелперы, DOM, модалки, меню
    demo.js              демо-студия и «Демо-процесс» (локальный режим)
    views/               главные по ролям: ceo (CEO), pm (PM), rm (RM «Релизы»), home + employee (сотрудник, лид);
                         apps (приложения: канбан, карточка, разбивка), release (карточка релиза), flows (флоу юнита),
                         myboard (моя доска), dev (режим разработчика); board, task, settings, units, people, admin, palette…
    styles.css
test/                    backend, roles, flow (Tasks 2.0: роли, приложения, этапы, релиз, дашборды), admin-users (Edge Function)
docs/CONCEPT.md          концепция Tasks 2.0: роли и верхнеуровневый менеджмент
.github/workflows/deploy.yml
```

Изменение схемы — дописать в `supabase/schema.sql` идемпотентные команды (`create … if not exists`, `alter table … add column if not exists`) и выполнить их в SQL Editor.
