# Tasks 2.0 — роли и верхнеуровневый менеджмент

Концепция пересборки (2026-10-26). Старая иерархия (юниты App → Managers → MVP → команды, передача вниз, мастер структуры) заменяется этой моделью; задачи, ревью, уведомления, ссылки, поля и личные доски переиспользуются.

## Сущности

- **Юнит** — направление: Gold / RF / MVP (плоский список, без уровней). В юнит добавлены люди: PM, RM, лиды, сотрудники. Задачи юнита можно назначать только его людям.
- **Приложение (App)** — отдельная постоянная сущность: название, юнит (CEO переносит между юнитами), статус, иконка/цвет, ссылки и инфо-поля (стор, bundle, версия…). У приложения — история работ: «Новое приложение», апдейты, реджекты.
- **Статусы приложения** — настраиваемый список (по умолчанию: В разработке → Релиз → Ревью Apple → В сторе / Реджект). Ставится сам по ходу работ, CEO может поправить вручную.
- **Запрос** — задача от CEO по приложению (New App / апдейт / другое) → приходит PM юнита приложения (CEO может выбрать конкретного PM).
- **Этапы** — задачи, на которые PM раскладывает запрос по шаблону флоу с зависимостями: Дизайн → iOS → QA, Мета (ASO) параллельно; Релиз — последним. Следующий этап виден сразу, но заблокирован, пока не закрыт предыдущий. Этап может иметь свои подзадачи (дизайн декомпозируется внутри).
- **Релиз** — PM передаёт RM вручную, кнопка доступна только когда закрыты все этапы до релиза. Карточка релиза собирает нужную RM информацию (список настраивается).

## Роли

| Роль | Что видит и делает |
|---|---|
| **CEO** | Полный доступ. Два режима, переключатель в шапке: **Default** — только приложения: дашборд портфеля, канбан приложений, карточка приложения, постановка задач PM, приоритеты; **Admin** — всё: юниты, доски, задачи на любом уровне, панель админа. |
| **PM** | Свои юниты: запросы от CEO, декомпозиция по шаблону, доска юнита, контроль хода, передача в релиз. Дашборд: прогресс по приложениям, блоки и просрочки, продуктивность каждого сотрудника (KPI). |
| **RM** | Очередь релизов своих юнитов: готовые к релизу, на ревью Apple, реджекты. Карточка релиза со всей информацией. |
| **Lead** (Design / iOS) | Как сотрудник + ревью задач своей позиции, прямые задачи от PM. |
| **Сотрудник** | Свои задачи из всех своих юнитов — сгруппированы по юнитам, не в одной куче. |

У каждого: свой **дашборд** и своя **канбан-доска**. Колонки личной доски — свои, но четыре обязательные константы есть у всех: **To Do / In Progress / Review / Done**; свои колонки встают между ними и считаются как ближайшая константа слева — так статусы синхронизируются по иерархии.

## Режим разработчика

Только у аккаунта разработчика (флаг у человека), везде, включая прод.
- «Смотреть как…» — роль и конкретный человек, быстро, без перелогина.
- **Шорткаты-сценарии** — прогоняют флоу целиком (пример «New App»: CEO создаёт приложение → запрос PM → декомпозиция по шаблону → назначения исполнителям). Набор шорткатов пополняется по запросу.
- Всё, что создано шорткатом, помечено «тест»: не шлёт уведомления реальным людям, видно только разработчику, удаляется одной кнопкой «Удалить тестовые данные».

## Этапы работы

1. **Модель и роли** — схема (роли, юниты, приложения, статусы, этапы с зависимостями, тест-флаг), права в базе, навигация по ролям, переключатель CEO Default/Admin, каркас режима разработчика + шорткат New App.
2. **CEO** — дашборд портфеля, канбан приложений, карточка приложения (быстрый доступ к инфо — настраиваемый), постановка задач.
3. **PM** — шаблоны флоу и декомпозиция, доска юнита, передача в релиз, дашборд и KPI сотрудников.
4. **RM** — очередь релизов, карточка релиза с настраиваемой информацией.
5. **Сотрудники и лиды** — дашборды, личный канбан с константами, ревью.
6. **Уборка** — убрать старые уровни/мастер, демо-данные под новую модель, документация.

Каждый этап — тесты логики и прав + проверка в превью за нужную роль.
