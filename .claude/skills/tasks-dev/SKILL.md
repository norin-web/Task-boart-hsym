# Tasks: как работать

## 0. Перед началом
Прочитай в репо `HANDOFF.md` (состояние, порядок выкатки, принципы интерфейса), `README.md` и `docs/CONCEPT.md` (роли и модель Tasks 2.0). Принятые там решения не обсуждай заново.

Отвечай коротко, по-русски, простыми словами, предлагай свои решения. Открытые вопросы — по одному, меню с вариантами, рекомендация первой.

## 1. Запуск
- `npm install`, затем превью `tasks` из `.claude/launch.json` (`npm run dev`, http://localhost:5177).
- Без `.env.local` — локальный режим: та же схема `supabase/schema.sql` на PGlite (Postgres в браузере). Пустая главная → «Заполнить демо-данными»: юниты Gold / RF / MVP, все роли, приложения на всех стадиях.
- Вход локально — аккаунт «Разработчик» (CEO + режим разработчика). Роли: Режим разработчика (`#/dev`, ⌥D) → «Смотреть как» — локально это настоящий вход под человеком; «Вернуться к себе» — там же.
- API из консоли превью: `const {call} = await import('/src/api.js'); await call('getCeoDashboard', {})`.
- Пустая тулза: профиль → «Очистить локальную базу».
- База локального режима — своя у каждой вкладки и браузера. Работает одна вкладка (Web Locks): вторая показывает «уже открыт в другой вкладке».

## 2. Как устроен код
- Вся бизнес-логика — `web/src/backend.js` (одинаково на Supabase и PGlite). Ошибки — `fail(msg, code)`.
- Права — в базе: RLS, триггеры и security definer функции в `supabase/schema.sql`; интерфейс только прячет недоступное.
- Схема — только идемпотентно (`if not exists`, `create or replace`, `drop policy if exists`): файл целиком выполняется на проде поверх старой версии.
- Экраны — `web/src/views/*`, DOM через `h()` и `fill()` из `ui.js`; состояние — `S` в `state.js`; маршруты и главная по роли — `router.js`.
- Главные по ролям: CEO — `ceo.js`, PM — `pm.js`, RM — `rm.js`, сотрудник и лид — `home.js` + `employee.js`; приложения — `apps.js`, релиз — `release.js`, личная доска — `myboard.js`, режим разработчика — `dev.js`, демо — `demo.js`.
- Карточку задачи вне доски открывай `peekTask()` — поверх страницы.
- Блок главной — объект в `BLOCKS` и `renderLayout`; должен жить и в узкой колонке (container queries, у grid — `grid-template-columns: minmax(0, 1fr)`).
- Цвета — только токены из `:root` в `styles.css` (светлая и тёмная тема, контраст текста ≥ 4.5:1).

## 3. Делать
1. Логика → `backend.js`, правка схемы → `schema.sql`, сразу тест в `test/` (права — в `roles.test.js` через `api.as(person, …)`, флоу — `flow.test.js`).
2. Интерфейс — минимально и спокойно: без прыгающих панелей и полных перерисовок, правки на месте, ничего не уводит со страницы. Принципы — `HANDOFF.md` → «Принципы интерфейса».
3. Сложный UX — сначала 2–3 варианта, потом делать.

## 4. Проверить
- `npm test` и `npx vite build` — зелёные.
- В превью: нужная роль, консоль без ошибок, широкий экран и телефон 375px, светлая и тёмная тема.
- Перетаскивание (Sortable, forceFallback) инструментом браузера не проверить — пошаговые `pointerdown → pointermove ×20 → pointerup` из JS.
- Тестовые данные после проверки — удали («Удалить тестовые данные» в режиме разработчика или «Очистить локальную базу»), роль — верни.
- В ответе честно: что проверено и чем, что нет.

## 5. Git и прод
- Коммить после проверки; сообщения по-русски, коротко; без Co-Authored-By и пометок ИИ.
- **Не пушить без команды владельца.** Push в `main` = деплой сайта на Cloudflare (https://taskmanager.cam, домен в `wrangler.jsonc`, workers.dev выключен; GitHub Pages отключён). Прод — Tasks 2.0 (с 2026-10-29); если менялась схема — сначала владелец выполняет `supabase/schema.sql` в Supabase SQL Editor, потом push (порядок — `HANDOFF.md` → «Выкатка на прод»).
- Секретный ключ Supabase (service role) — только в Edge Function, не во фронт и не в репо.

## 6. После работы
- Обнови в `HANDOFF.md` раздел «Состояние» и «Дальше по плану»: что сделано, где остановились, что дальше.
- Решение, которое должно жить дальше, — тоже в `HANDOFF.md` (или `docs/CONCEPT.md`, если меняет модель).

## Частые ошибки
- Заменять то, что заказчик ценит (статистику, «Требует внимания»), вместо того чтобы добавлять.
- Делать настройку формой-списком там, где нужна наглядность (перетаскивание, меню с галочками).
- Блок рассчитан только на широкую колонку — в узкой разъезжается.
- Мерить прод состоянием локальной базы: на проде схема старая.
